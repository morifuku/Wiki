🟪 5Gデモ構築¶

🟩 5GCN（コアネットワーク）¶

性能面のざっくりした傾向としては、制御プレーンの遅延はOpen5GSが最も良く、データレートはOAIが最高、リソース消費はfree5GCが最小という評価があります。

🟨 OAI CN5G（OpenAirInterface Core Network）/ Durantaプロジェクト¶

  • 3GPP準拠の5G SAコアです。ベアメタル/VM、Docker Composeでのコンテナ展開、OpenShift/Kubernetes上でのHelm Chart展開に対応しています。社内LANで進めているOpenShift環境にもHelmでそのまま載せられます。ライセンスはOAI Public License。

  • 将来的に Durantaプロジェクト に移行予定。ソースコードはすでにDurantaプロジェクトのGitHubリポジトリにも配置されている。

🟨 Open5GS¶

C言語で書かれています。Release 16準拠の4G/5G NSA対応EPCと5G SAコアを実装しており、ライセンスはAGPLv3です。安定性とドキュメントの充実から最も広く使われていると評価されており、最初の一本ならこれが無難です。

🟨 free5GC¶

Go言語で書かれています。台湾NYCUの研究者が2019年に作った、最初のオープンソース5Gコアで、2024年にLinux Foundation傘下に入りました。N3IWF（非3GPPアクセス）などを試すのに向いています。

🟨 SD-Core（Aether / ONF系）¶

クラウドネイティブ寄りの5Gコアです。論文ではOpen5GS・OAI・free5GCと並ぶ主要プラットフォームとして比較されています。Kubernetes前提で使います。

🟨 Magma¶

もともとはFacebook発で、現在はLinux Foundationのプロジェクトです。EPC/5GCに加えて、アクセスゲートウェイや管理機能まで含みます。主な用途は通信事業者や地域ネットワーク向けです。

🟩 5GRAN¶

🟨 Durantaプロジェクト¶

USRPで実際の電波を出し、市販のQuectel 5Gモデムを接続する構成まで組めます。RFsimulatorモードを使えばSDRなしでも動きます。

🟨 UERANSIM¶

gNBとUEのソフトウェアシミュレータです。無線機がなくても、コアへのRegistrationやPDUセッションを確認できます。コアだけ試すなら必須級です。

🟨 srsRAN Project / OCUDU¶

C++製のgNBです。OCUDUはsrsRAN-Projectのフォークです。

🟨 PacketRusher¶

Go製のUE/gNBシミュレータで、負荷試験向けです。

🟩 仮想化インフラ¶

  • 5GCやRANの動きを学ぶなら、k3sやkubeadmにOpen5GS／free5GC、UERANSIMを組み合わせるのが最小構成で、手軽です。

  • 商用のテレコム基盤の運用を体験するなら、OpenShift SNO（またはOKD）にworkerを追加し、free5GCやOAIを載せるのがおすすめです。

  • 低遅延のvRAN、PTP、リアルタイム処理を見たいなら、StarlingXかOpenShiftのTelco RANプロファイルが向いています。

  • ラボ規模では、商用の基盤よりも素のKubernetesやOSS版の基盤が使われることが多いです。よく見かける構成は次のとおりです。

🟨 素のKubernetes＋OSSの5GC/RAN（いちばん多い構成）¶

  • k3s、kubeadm、MicroK8s、kindなどで軽量なクラスタを作り、その上でOpen5GS、free5GC、OAI（OpenAirInterface）のCN/RANをHelmで載せる構成です。

  • 研究室やPoC（概念実証）、個人の検証ではほぼこれが基本です。マシン1台でも動きます。

  • ONFのAether（SD-Core）も、Kubernetes上で動く5GC一式として、大学や企業の私設5Gラボで使われています。

🟨 OKD／OpenShift SNO¶

  • 商用に近い形で検証したい場合の定番です。SR-IOV Operator、PTP Operator、NUMA対応のスケジューリングなど、テレコム向けの機能をそのまま試せます。

  • 必要リソースが大きく、SNOでも8コア・32GB前後は欲しいところです。free5GCやOAIはOpenShift上での動作手順も公開されています。

🟨 StarlingX（Wind Riverの基盤のOSS版）¶

  • AIO-SX（1台構成）で動かせます。vRAN/エッジ寄りの検証、特にリアルタイムカーネルやPTPを試したいときに向いています。

  • 情報量はOpenShiftより少なめで、構築の手間もやや大きいです。

🟨 OpenStack（VNF時代の構成を試す場合）¶

  • DevStack、MicroStack、Kolla-Ansibleなどで構築します。今はCNFが主流なので、新しく選ぶ理由は少なくなっています。

🟨 自動化・オーケストレーション層のOSS¶

  • Nephio（Kubernetesネイティブなネットワーク自動化）や、欧州キャリア主導のSylvaは、上記の基盤の上に載せてラボで評価されています。

🟩 最初の一歩としての構成例¶

  1. ソフトだけで完結させる：Open5GS（またはOAI CN5G）とUERANSIMを、1台のUbuntuかVMに入れます。半日ほどでPDUセッションの確立と ping まで確認できます。

  2. OAIで統一する：OAI CN5GをDocker Composeで立て、Duranta gNBとOAI UEをRFsimulatorモードで動かします。

  3. 実機で電波を出す：2.の構成にUSRP（B210など）と5Gモデム、テスト用SIMを加えます。実際に電波を出すので、電波法上の扱い（実験試験局の免許やシールド環境など）は事前に確認が必要です。
