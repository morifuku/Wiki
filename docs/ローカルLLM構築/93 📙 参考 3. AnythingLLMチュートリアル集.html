🟩 Q: AnythingLLMのチュートリアル¶

公式ドキュメントと外部記事のチュートリアルを、目的別にまとめます。

🟨 全体像をつかむもの（GUI・RAG中心）¶

  • DataCamp の解説記事：DockerとOllamaでのインストールから、社内文書とチャットするためのRAGの組み方、Open WebUIやChatGPTとの比較まで扱っています。2026年2月の記事で、最初に読むならこれが手頃です。

    • https://www.datacamp.com/blog/anythingllm

  • Better Stack のガイド：ワークスペースをプロジェクトごとに分ける使い方の例です。PythonのプロジェクトとJavaScriptのプロジェクトでワークスペースを分ければ、文書も会話も完全に別々になる、という形で説明しています。

    • https://betterstack.com/community/guides/ai/anythingllm-local-llm/?format=markdown

🟨 プログラムから使うもの（拡張の口）¶

  • 公式：Agent Flows のチュートリアル：公式ドキュメントに「Tutorial: HackerNews Flow」があり、Webスクレイパー、API呼び出し、LLM指示、ファイルの読み書きといったブロックを使います。

    • https://docs.anythingllm.com/

  • 公式：カスタムAgent Skill の開発者ガイド：plugin.json と handler.js のリファレンス付きです。handler.js では handler 関数を持つ runtime オブジェクトを export する決まりになっています。

    • https://docs.anythingllm.com/agent/custom/handler-js

  • DEV Community の実例：Make.com のWebhookを叩くスキルを作る記事です。スキルのフォルダは、Macならホームディレクトリの Library/Application Support/anythingllm-desktop/storage/plugins/agent-skills にあると書かれています。1つ作ってみる手本としてちょうどよい長さです。

    • https://dev.to/drunnells/writing-an-anythingllm-custom-agent-skill-to-trigger-makecom-webhooks-1dn0

  • Developer API：Swaggerのドキュメントが /api/docs にあり、ワークスペースの管理、文書の埋め込み、チャットの送信をプログラムから行えます。動いているインスタンスでこのページを開けば、そのまま試せます。

    • https://www.datacamp.com/blog/anythingllm

  • 公式CLI（anything-llm-cli）：git diff | any prompt "Write a commit message for these changes" のように、パイプでつないで使えます。

    • https://awesome.ecosyste.ms/projects/github.com%2Fmintplex-labs%2Fanything-llm-cli

🟨 Developer API を一番手短に試すなら¶

APIのベースは http://localhost:3001/api、主なエンドポイントは POST /api/v1/workspace/{slug}/chat で、認証には Settings > Developer API で発行したBearerトークンを使います。

curl -X POST http://localhost:3001/api/v1/workspace/melsec/chat \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"message":"MCプロトコルの3Eフレームの構成は？","mode":"query"}'

mode:"query" にすると、取り込んだ文書だけを根拠に答えます。この curl が通れば、同じリクエストを libcurl で送るだけでC/C++から使えます。

ひとつ注意があります。複数の利用者が使うアプリから呼ぶ場合は、利用者ごとにスレッドを分ける必要があります。ワークスペースの /chat をそのまま使うと、全員が同じ会話に入ってしまったので、ユーザーごとにスレッドを作って解決したという報告があります。
